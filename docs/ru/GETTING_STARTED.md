# Быстрый старт: сравнить, подключить и попробовать методику

Эта страница - для человека, который впервые открыл репозиторий и хочет понять, что делать дальше.

Сначала выберите свой сценарий. Не нужно заранее читать архитектуру, все навыки и внутренние правила.

Если непонятно, **что именно написать агенту** для уточнения задачи, исследования, реализации, проверки или коррекции, используйте [короткую человеческую инструкцию по общению с ИИ](AI_COMMUNICATION.md). Названия внутренних навыков знать не требуется.

## Шаг 1. Выберите, что вы хотите сделать

### Я только хочу сравнить методику со своим текущим процессом

Ничего не устанавливайте. Перейдите к шагу 2: агент или вы сами сначала смотрите проект **только на чтение** и решаете, есть ли вообще смысл что-то подключать.

### Я начинаю новый 1С-проект

Пройдите шаги 2-6. Самый простой путь - сначала дать агенту ссылку на методику и доступ к проекту, а копирование выполнять только после его оценки и вашего разрешения.

### У меня уже зрелый проект с инструкциями, skills и своим процессом

Не копируйте пакет целиком автоматически. Сначала сравните существующий процесс с методикой и выберите один из вариантов:

- ничего не менять;
- подключить только недостающие совместимые части;
- подключить полный пакет, только если он не создаст второго владельца тех же правил.

Подробно этот сценарий разобран в ["Источники и подключение методики"](SOURCES_AND_ADOPTION.md).

## Если вы работаете вообще без Git

Это допустимый, но более слабый по истории вариант.

Не нужно сначала внедрять Git только ради того, чтобы попробовать методику. Используйте существующие исходники, трекер или долговременный документ задач и способ сохранять состояние до и после изменений.

Практический маршрут: [Работа без Git: что можно делать сейчас](NO_GIT.md).

## Шаг 2. Сначала оцените проект без изменений

### Вариант A - агент сначала сравнивает всё сам

Это рекомендуемый путь, если агент умеет читать репозитории/файлы проекта.

**Что нужно:**

- ссылка на `Megabonstr/1c-ai-development-methodology`;
- доступ агента на чтение к вашему проекту;
- никакого разрешения на запись пока не требуется.

**Что передать агенту:**

```text
Посмотри эту методику и мой 1С-проект.
Пока ничего не меняй.
Сравни существующие инструкции, skills, структуру проекта и процесс разработки.
Скажи кратко:
- что методика добавит;
- что у нас уже есть;
- где есть конфликт или дублирование;
- что лучше: ничего не ставить, подключить выборочно или подключить пакет целиком.
Технические факты проекта проверь сам; спрашивай меня только там, где действительно нужен выбор.
```

**Ожидаемый результат:** короткая рекомендация без изменений проекта.

**Как проверить:** в `git diff`/списке изменённых файлов или в файловой системе проекта не должно появиться новых файлов от методики.

### Вариант B - оценить вручную

Проверьте пять вещей:

1. Где находятся канонические исходники: EDT, XML/Конфигуратор или другой явно определённый путь?
2. Есть ли уже `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, Copilot instructions или другие инструкции для агентов?
3. Есть ли уже проектные skills и кто ими владеет?
4. Где сохраняются задачи, решения и проверенные версии результата?
5. Не будет ли `.1c-ai` дублировать уже работающие правила проекта?

Если ответы неясны, это повод продолжить оценку, а не устанавливать пакет вслепую.

## Шаг 3. Получите точную версию методики

Текущий способ подключения - **ручная закреплённая копия точной ревизии** (`MANUAL_PINNED_COPY`). Автоматического безопасного installer/update/uninstall пока нет - это отдельная работа [#2](https://github.com/Megabonstr/1c-ai-development-methodology/issues/2).

Поэтому перед копированием нужно знать полный commit SHA методики.

### Если у вас есть Git

**Где выполнять:** в PowerShell/терминале на своём компьютере, не внутри 1С.

**Что нужно:** установленный Git и папка, куда можно скачать методику.

Пример:

```powershell
New-Item -ItemType Directory -Force C:\AI | Out-Null
Set-Location C:\AI
git clone https://github.com/Megabonstr/1c-ai-development-methodology.git
$MethodologySHA = (git -C C:\AI\1c-ai-development rev-parse HEAD).Trim()
$MethodologySHA
```

**Что изменит команда:** создаст только локальную копию методики в `C:\AI\1c-ai-development`. Ваш 1С-проект она пока не меняет.

**Ожидаемый результат:** PowerShell выведет 40-символьный SHA.

**Как проверить:** выполните:

```powershell
git -C C:\AI\1c-ai-development status
git -C C:\AI\1c-ai-development rev-parse HEAD
```

SHA из второй команды должен совпадать с `$MethodologySHA`.

### Если Git не установлен

1. Откройте в GitHub **конкретный commit** методики, который хотите использовать.
2. Скопируйте его полный SHA.
3. Скачайте ZIP именно этой ревизии и распакуйте, например, в `C:\AI\1c-ai-development`.

**Что изменится:** появится только локальная папка методики.

**Как проверить:** сохраните SHA рядом с проектом/в заметке до подключения. Без точного SHA не называйте копию закреплённой.

## Шаг 4. Подключите пакет - агентом или вручную

### Путь A - агент-assisted adoption

После шага 2 дайте агенту **явное разрешение** только на выбранный вариант подключения.

Например:

```text
Разрешаю подключить методику к этому проекту по выбранному варианту.
Не перезаписывай существующие проектные инструкции и skills.
Зафиксируй точный SHA методики.
После изменений покажи только, что добавлено/изменено и как проверена структура.
```

Агент должен сохранить проектные правила, не создавать дублирующие `1c-ai-*` skills в клиентских каталогах и зафиксировать точную ревизию методики.

### Путь B - первый ручной copy для нового/чистого проекта

Используйте этот вариант только если в проекте **ещё нет** `.1c-ai` и skills `1c-ai-*`.

**Где выполнять:** PowerShell на компьютере, где лежат методика и ваш проект.

**Что нужно:**

- `$MethodologySHA` из шага 3;
- путь к распакованной/клонированной методике;
- путь к вашему проекту;
- резервная копия или Git-коммит проекта перед изменением - желательно.

Пример:

```powershell
$Method = "C:\AI\1c-ai-development"
$Project = "C:\AI\My1CProject"

if (-not $MethodologySHA) { throw "Methodology SHA is required" }
if (Test-Path "$Project\.1c-ai") { throw ".1c-ai already exists - compare before updating" }
if (Get-ChildItem "$Project\.agents\skills" -Directory -Filter "1c-ai-*" -ErrorAction SilentlyContinue) {
    throw "1c-ai-* skills already exist - compare before updating"
}

Copy-Item "$Method\.1c-ai" "$Project\.1c-ai" -Recurse
New-Item -ItemType Directory -Force "$Project\.agents\skills" | Out-Null
Get-ChildItem "$Method\.agents\skills" -Directory -Filter "1c-ai-*" | ForEach-Object {
    Copy-Item $_.FullName "$Project\.agents\skills\$($_.Name)" -Recurse
}
```

**Что изменит команда:** добавит в проект машинный пакет `.1c-ai/**` и skills `.agents/skills/1c-ai-*`. Она не должна менять исходники 1С.

**Ожидаемый результат:** обе папки появились, существующие проектные skills вне `1c-ai-*` остались на месте.

**Как проверить:**

```powershell
Test-Path "$Project\.1c-ai\START_HERE.md"
Get-ChildItem "$Project\.agents\skills" -Directory | Select-Object Name
```

Первый результат должен быть `True`; список skills должен содержать `1c-ai-*` и при этом не терять ваши прежние каталоги.

### Подключите вход для вашего агента

Методике нужен один короткий маршрут из того файла инструкций, который уже использует ваш AI-клиент: например `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` или `.github/copilot-instructions.md`.

Если такого файла нет, можно взять минимальный адаптер из репозитория методики.

Если файл уже есть - **не заменяйте его**. Добавьте только маршрут к `.1c-ai/START_HERE.md`, сохранив проектные правила.

Ожидаемый результат: агент проекта умеет попасть в методику, но ваши собственные инструкции остаются владельцем проектной специфики.

## Шаг 5. Зафиксируйте карту проекта и первую задачу

Создайте в корне проекта `PROJECT_AI.md`. Это короткая карта, а не новая база знаний.

Минимальный пример для EDT-проекта:

```text
Project: My1CProject
MethodologyPackage: Megabonstr/1c-ai-development-methodology @ <exact SHA from step 1>
CoordinationScope: whole project
OwningCoordinator: Coordinator Main
AuthoritativeSource: EDT project .
ExecutionProfile: .1c-ai/profiles/1c-edt-mcp/PROFILE.md

DO_NOT_TOUCH:
- production infobase
- unrelated metadata
```

Для XML-проекта:

```text
Project: My1CProject
MethodologyPackage: Megabonstr/1c-ai-development-methodology @ <exact SHA from step 1>
CoordinationScope: whole project
OwningCoordinator: Coordinator Main
AuthoritativeSource: XML source ./src
ExecutionProfile: .1c-ai/profiles/1c-xml-configurator/PROFILE.md

DO_NOT_TOUCH:
- production infobase
- unrelated metadata
```

EDT/MCP не являются обязательными для всей методики: профиль выбирается по тому, где **реально живут исходники** вашего проекта.

Эти `CoordinationScope` и `OwningCoordinator` - долговременный default проекта. Обычная маленькая задача может наследовать их и не повторять в каждом тексте задачи, пока проектный default остаётся явным и актуальным.

Теперь создайте маленькую задачу в том долговременном месте, которое уже использует проект.

GitHub [Issue](GIT_GITHUB_FLOW.md#issue) - рекомендуемый вариант для Git-backed проекта, но не универсальное требование. Если термин непривычен: это обычная карточка задачи в GitHub, где сохраняются цель, решения, ссылки на изменения и итог.

Если Git/GitHub не используются, нужен **уже работающий** проектный носитель задач/решений с устойчивым идентификатором. Пакетный Gitless backend пока не поставляется ([#1](https://github.com/Megabonstr/1c-ai-development-methodology/issues/1)); без существующего носителя не объявляйте Gitless lifecycle настроенным.

Пример первой задачи:

```text
Что должно измениться:
В отчёте по остаткам добавить отбор по выбранному Складу на стороне запроса.

Что не менять:
Состав колонок, алгоритм расчёта количества и права текущего пользователя.

Как проверить:
Сформировать отчёт для двух разных складов и убедиться,
что в каждом варианте показаны только данные выбранного склада,
а без отбора результат остался прежним.
```

Если задача уже ясна, этого достаточно: не нужен отдельный research или архитектурная церемония.

## Шаг 6. Проверьте подключение и сделайте первый цикл

### Проверка структуры

Убедитесь, что:

- `.1c-ai/START_HERE.md` существует;
- `.agents/skills/1c-ai-*` существуют;
- в `PROJECT_AI.md` записан точный `MethodologyPackage @ SHA`;
- ваш исходный `AGENTS.md`/`CLAUDE.md`/другие инструкции не были затёрты;
- проектные skills вне `1c-ai-*` сохранились.

Это **ручная проверка структуры**, а не deterministic installer validation.

### Первый запуск агента

Передайте ему только идентификатор задачи:

```text
Прочитай инструкции проекта и PROJECT_AI.md.
Работай по задаче <ссылка / номер / идентификатор>.
Не выходи за её границы.
Сначала проверь реальные исходники и стандартные механизмы,
потом внеси минимальное изменение и выполни нужные проверки.
```

После выполнения проверьте:

- понятно, что именно изменено;
- известна точная версия результата;
- выполнены проверки, нужные именно этой задаче;
- реальный пользовательский сценарий проверен, если это требовалось;
- непроверенное не выдано за проверенное;
- новый агент сможет продолжить работу по сохранённой задаче без пересказа чата.

Если это выполняется - первый цикл завершён.
