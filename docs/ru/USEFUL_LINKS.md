# Полезные ссылки для разработки 1С с ИИ

Этот файл - практический каталог для человека.

Он **не является реестром происхождения проекта** и не означает, что перечисленные инструменты обязательны.

Канонический реестр источников, которые реально повлияли на эту методику: [`sources/SOURCES.md`](../../sources/SOURCES.md).

Проверено по первичным upstream-источникам 19 сентября 2026 года. Перед установкой всегда сверяйте актуальную версию, совместимость с вашей платформой/EDT и лицензию.

## ИИ, MCP и навыки

- [DitriXNew/EDT-MCP](https://github.com/DitriXNew/EDT-MCP) - execution/integration surface для агента в 1C:EDT: project diagnostics, BSL, формы, query validation, metadata, запуск/debug и YAxUnit. Upstream на 19.09.2026 заявляет EDT 2026.1/2026.2 (E2E/Conformance - 2026.2), latest release - v2.17.1. Успешный MCP-вызов не равен доказанной бизнес-корректности. Лицензия AGPL-3.0.

- [Nikolay-Shirokov/cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills) - большой набор навыков для XML-исходников, Конфигуратора, форм, СКД, расширений, внешних обработок и веб-проверок. Основной практический источник для профиля XML + Конфигуратор.

- [brake71/1c-ssl-skills](https://github.com/brake71/1c-ssl-skills) - специализированный навык по БСП: помогает отличать публичный программный интерфейс от служебной реализации и сверять методы с реальными исходниками. Полезен также как пример компактного маршрутизируемого навыка.

- [vandalsvq/edt1c-ai-template](https://github.com/vandalsvq/edt1c-ai-template) - пример организации рабочего репозитория EDT с ИИ: инициализация проекта, разделение шаблонных и проектных файлов, синхронизация общих правил. Верхнеуровневая лицензия проекта на момент проверки явно не определена - использовать как источник идей, не копировать без отдельной проверки.

- [Arman-Kudaibergenov/1c-ai-development-kit](https://github.com/Arman-Kudaibergenov/1c-ai-development-kit) - крупный набор правил, агентов и навыков для 1С. Полезен для сравнения подходов и организации большого набора возможностей; не стоит автоматически переносить всю его структуру в каждый проект.

- [Untru/1c-mcp](https://github.com/Untru/1c-mcp) - поддерживаемый каталог MCP-серверов и ИИ-инструментов для 1С. Удобная точка поиска нового инструмента под конкретную задачу; сам каталог не является архитектурным стандартом.

- [anthropics/skills](https://github.com/anthropics/skills) - примеры сложных навыков в формате Agent Skills. У отдельных навыков разные условия лицензирования, поэтому нельзя считать весь репозиторий единым набором свободно копируемых материалов.

## Тестирование

- [BIA-Technologies/YAxUnit](https://github.com/bia-technologies/yaxunit) - тестовый движок 1С с [утверждениями и отчётами](https://bia-technologies.github.io/yaxunit/). Latest release при проверке - 25.12. Полезен для уровня TEST: PASS доказывает только реально выполненные тесты/утверждения и не заменяет UI/runtime/RLS/user acceptance, если они не были частью теста.

- [BIA-Technologies/edt-test-runner](https://github.com/bia-technologies/edt-test-runner) - запуск и отладка YAxUnit из EDT. Первичная инструкция по установке не подтверждает 2026.x и содержит оговорки о конфликтах зависимостей на более новых EDT, поэтому для современной линии статус - `UNKNOWN / проверить`. При EDT-MCP отдельный инструмент запуска может быть не нужен, если требуется только запуск тестов агентом.

- [Pr-Mex/vanessa-automation](https://github.com/Pr-Mex/vanessa-automation) - BDD, пользовательские и сквозные сценарии 1С. Подходит для задач, где нужно проверить реальное поведение интерфейса, а не только код.

Компонент VanessaExt отдельно в основной список не вынесен: он является частью Vanessa Automation. Старый Vanessa-ADD также не дублируется в списке по умолчанию.

## Стандарты и статический анализ

- [Система стандартов и методик разработки конфигураций 1С](https://its.1c.ru/db/v8std) - первичный нормативный источник для стандартов разработки 1С.

- [zeegin/v8std](https://github.com/zeegin/v8std) - удобный для человека индекс стандартов и связей с диагностическими инструментами. Используйте его для навигации, а значимые нормативные утверждения сверяйте с первичным источником 1С/ИТС.

- [1C-Company/v8-code-style](https://github.com/1C-Company/v8-code-style) - официальный инструмент 1С с STATIC-проверками BSL, метаданных, форм, прав и языка запросов по стандартам 1С. Upstream указывает включение в EDT 2021.3+ и публикует 0.8.0 для EDT 2026.2. Зелёный набор diagnostics не заменяет build/runtime/native/user acceptance.

- [1c-syntax/bsl-language-server](https://github.com/1c-syntax/bsl-language-server) - независимый community LSP/static analyzer для BSL; [диагностики](https://1c-syntax.github.io/bsl-language-server/diagnostics/) настраиваются, часть отключена по умолчанию. Latest release при проверке - v1.0.7. Это дополнительный STATIC-сигнал, а не официальный владелец стандартов 1С; deprecated/version diagnostics зависят от используемой reference-информации.

- [otymko/bslls-connector-for-edt](https://github.com/otymko/bslls-connector-for-edt) - подключение BSL Language Server к EDT. Последний релиз v0.3.0 фиксирует миграцию на EDT 2025.1; явного первичного подтверждения EDT 2026.1/2026.2 нет, поэтому совместимость с современной линией нужно проверить.

- [1C-Company/dt-project-checks](https://github.com/1C-Company/dt-project-checks) - официальный плагин 1С для **структурной целостности EDT-проектов**, входящий в EDT. Его PASS не является проверкой бизнес-логики; upstream сам отправляет style/logical/standards checks в отдельный проект v8-code-style.

- [1C-Company/1c-edt-issues](https://github.com/1C-Company/1c-edt-issues) - официальный трекер проблем и пожеланий EDT. Полезно проверять его при странном поведении IDE или плагинов.

## БСП, типовые исходники и проверенные примеры

- [1c-syntax/ssl_3_1](https://github.com/1c-syntax/ssl_3_1) - открыто доступные исходники БСП 3.1. Это репозиторий сообщества, а не официальный GitHub фирмы 1С; используйте для исследования конкретной версии.

- [1c-syntax/ssl_3_2](https://github.com/1c-syntax/ssl_3_2) - исходники БСП 3.2. Полезны для проверки развития механизмов на новых версиях. Версию БСП проекта всегда определяйте по самому проекту.

- [1C-Company/ssl-support](https://github.com/1C-Company/ssl-support) - официальный плагин EDT для разработки конфигураций на БСП. Текущий целевой файл сборки (`source target`) проекта указывает EDT 2026.2, но публичная таблица готовых установочных репозиториев в README заканчивается на EDT 2022.1; наличие подходящего готового пакета для вашей линии нужно подтверждать отдельно.

- [BlizD/Tasks](https://github.com/BlizD/Tasks) - большой открытый прикладной проект 1С; полезен как источник реальных решений, но не как нормативный стандарт.

- [cpr1c/tools_ui_1c](https://github.com/cpr1c/tools_ui_1c) - богатый набор инструментов для управляемых форм, запросов, СКД, метаданных и HTTP. Хороший источник идей и реализаций; лицензия GPL-3.0 требует осторожности при копировании.

## EDT: плагины и инфраструктура

- [marmyshev/edt-plugins](https://github.com/marmyshev/edt-plugins) - каталог плагинов EDT. Используйте как индекс; совместимость каждого плагина с вашей линией EDT проверяйте у первичного источника.

- [YanSergey/edt.cf_builder](https://github.com/YanSergey/edt.cf_builder) - импорт и экспорт CF/CFE из EDT. Последний опубликованный релиз 1.3.5 адаптирован под EDT 2022.2; README помечает версии для 2025.2/2026.1 как готовящиеся, а 2026.2 не фиксирует, поэтому для текущей EDT совместимость - `UNKNOWN / проверить`.

- [Jimmo910/edt-plugin-pack](https://github.com/Jimmo910/edt-plugin-pack) - удобный сайт обновлений / офлайн-набор, который сейчас заявляет проверку установки на EDT 2026.1 и 2026.2. Используйте как агрегатор/способ установки, а совместимость, происхождение и лицензию каждого компонента всё равно сверяйте у его первичного проекта.

Зеркало Disable Editing в основной список не включено: для рекомендуемой ссылки лучше использовать первичный источник, когда он точно установлен.

## Как пользоваться этим списком

Не подключайте всё сразу.

Для конкретной задачи порядок обычно такой:

1. текущий проект и его реальные исходники;
2. типовая конфигурация/БСП и официальный программный интерфейс;
3. официальный стандарт или официальный инструмент проверки;
4. один подходящий проверенный внешний источник;
5. собственная реализация только для оставшегося пробела.

Каталог помогает найти источник. Он не отменяет [правило "сначала проверенные источники"](SOURCE_FIRST.md) и не превращает сторонний репозиторий в обязательную зависимость проекта.
