# Обновление общих инструкций и skills в существующих 1С-проектах

Короткая ссылка для агента: [PROJECT_REFRESH_AGENT_START.txt](../../PROJECT_REFRESH_AGENT_START.txt).

Это маршрут для **уже подключённой** методологии, когда в проекте есть
PROJECT_AI.md со строкой MethodologyPackage, а общие файлы расположены в
.1c-ai/** и .agents/skills/1c-ai-*/**. Первая установка, выборочная интеграция
в зрелый проект и удаление пакета сюда не входят.

## Где живут главные skills

Общие skills и правила хранятся только в репозитории
[1c-ai-development-methodology](https://github.com/Megabonstr/1c-ai-development-methodology):

- .1c-ai/** — правила, маршруты, профили;
- .agents/skills/1c-ai-*/** — универсальные skills.

Проектные AGENTS.md, PROJECT_AI.md, CODEX/** и skills с другими именами
принадлежат соответствующему рабочему проекту. Их нельзя перезаписывать
копией общей методологии. У EDT-MCP актуальную спецификацию инструментов
задают установленная версия, её live guide/schema и upstream
[DitriXNew/EDT-MCP](https://github.com/DitriXNew/EDT-MCP), а не устаревшие
примеры из копий навыков. Отдельный набор бизнес-навыков EDT-MCP живёт в
[agent/skills](https://github.com/DitriXNew/EDT-MCP/tree/master/agent/skills).
Копии с локальными доработками нужно **сравнивать с точным upstream-тегом**,
а не бездумно заменять: общий обновляющий скрипт их не трогает.

## Что передать агенту

Дайте ссылку на [стартовую инструкцию для обновления](../../PROJECT_REFRESH_AGENT_START.txt)
и короткое сообщение:

> Update the generic methodology package in this project from its recorded
> MethodologyPackage SHA to the latest accepted methodology main SHA.
> First audit the project's owners and show a conflict-free plan. Preserve
> project-specific policies and skills. Use a feature branch/PR and verify
> GitHub and local Git independently. Do not touch 1C source or runtime.

Агент сначала проверяет реальную структуру и установленную версию.
У зрелого проекта со своим каноническим набором правил результатом может быть
**не устанавливать** общий пакет или **обновить только согласованную часть**.

## Как устроено безопасное обновление

В методологии есть Python 3-скрипт
[scripts/refresh_existing_package.py](../../scripts/refresh_existing_package.py).
Он работает с двумя **локальными Git-копиями** и точной ревизией методологии.
Старый исходный SHA берёт из PROJECT_AI.md и сравнивает содержимое файлов:

| Состояние файла | Действие |
|---|---|
| Уже совпадает с новой ревизией | Пропустить |
| Совпадает со старой закреплённой ревизией | Обновить по разрешённому плану |
| Локально изменён относительно обеих ревизий | Остановиться без записи |

Обычный вызов **ничего не меняет**, а показывает план в JSON. Только параметр
--apply записывает изменения, причём требует чистую локальную Git-копию
на ветке feature/*. Он меняет только общие файлы и одну строку версии в
PROJECT_AI.md. Не создаёт коммит, не публикует GitHub PR и не трогает EDT.

Для первоначального подключения используйте
[быстрый старт](GETTING_STARTED.md) и
[правила подключения](SOURCES_AND_ADOPTION.md).

## GitHub и локальная копия — разные этапы

1. Агент изучает проект и предлагает точное обновление.
2. Локальный агент на чистой рабочей ветке выполняет план и --apply либо
   облачный агент готовит эквивалентный проверенный diff в GitHub.
3. Проверяется, что проектные инструкции, код 1С, секреты и специальные skills
   не изменились.
4. Изменения коммитятся и отправляются через PR по принятой схеме проекта.
5. После приёмки локальный агент отдельно выполняет Git fetch/pull
   принятого коммита и сверяет его с локальным HEAD и PROJECT_AI.md.

**Публикация PR не означает обновление файлов у вас на компьютере.**
Если агент не имеет доступа к локальной машине, честный статус —
LOCAL_SYNC=UNKNOWN. Это не ошибка и не повод заявлять, что всё уже
синхронизировано.

Подробный технический контракт:
[.1c-ai/core/PACKAGE_REFRESH.md](../../.1c-ai/core/PACKAGE_REFRESH.md).

Полный автоматический installer/update/uninstall с установочным manifest
и поддержкой выборочного обновления остаётся отдельной задачей
[issue #2](https://github.com/Megabonstr/1c-ai-development-methodology/issues/2).
