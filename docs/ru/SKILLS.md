# Навыки агентов

Этот документ - для человека.

Технические файлы навыков лежат в [`.agents/skills/`](../../.agents/skills/). Агент выбирает нужный навык через [router](../../.1c-ai/router/ROUTER.md) и не должен загружать их все сразу.

## Главное про роли

Навык - это рабочая инструкция для одного типа действий, а не отдельный обязательный агент.

Есть два основных логических режима:

- **главный координатор** - понимает исходный запрос, держит смысл и границы задачи, принимает решения по существенным неизвестным и передаёт исполнителю уже готовую задачу;
- **локальный исполнитель** - получает зафиксированную задачу, работает с реальным проектом, реализует, исправляет обычные технические ошибки, проверяет результат и возвращает точные доказательства.

Один физический агент может последовательно выполнять обе роли. Для маленькой задачи не нужны обязательные отдельные чаты или несколько агентов.

## Как проходит обычная задача

Если запрос сырой:

```text
человек
→ координатор приводит запрос к готовой задаче
→ при необходимости проверяет один факт или проводит большое исследование
→ фиксирует задачу
→ локальный исполнитель принимает её через task-bootstrap
→ реализация
→ review
→ нужные проверки/runtime
→ локальный результат + доказательства
→ координатор проверяет доказательства/приёмку
→ фиксирует принятую версию и один короткий итог
→ сообщает результат человеку
```

Если задача уже понятна и зафиксирована, первые шаги пропускаются:

```text
готовая задача
→ task-bootstrap
→ реализация
→ review
→ проверка
→ локальный результат
→ короткое завершение задачи координатором
```

## Обычный поиск и большое исследование - не одно и то же

### Один конкретный вопрос

`1c-ai-source-first-research` используется в двух режимах:

- координатор проверяет один факт, который влияет на решение;
- локальный исполнитель уточняет одну техническую деталь внутри уже принятой задачи.

Например:

> Какой публичный метод БСП подходит для этой операции в нашей версии?

Факт найден - поиск заканчивается.

### Большое исследование

`1c-ai-deep-research` - это работа координатора или делегированного исследователя для действительно широкого/дорогого решения.

Если локальный исполнитель во время реализации понимает, что нужен широкий V1/V2/V3 анализ архитектуры или продукта, он не начинает его как обычный технический lookup, а возвращает вопрос координатору.

Подробнее: [Глубокое исследование](DEEP_RESEARCH.md).

## GitHub handoff - не этап разработки

`1c-ai-github-handoff` не решает, что делать с продуктом, и не реализует задачу.

Это транспорт для Git-backed процесса: передать точную задачу, SHA, evidence handles и следующий разрешённый шаг между контекстами без пересказа всей истории.

Если Git/GitHub не используются, действует принятый проектом долговременный способ передачи состояния.

## Что локальный исполнитель обычно не читает

Ему не нужны по умолчанию:

- сырой диалог с человеком;
- вся история обсуждения координатора;
- README и философия методики;
- широкая история Issues/проекта;
- несвязанные исследования;
- все skills и все execution profiles сразу.

Он получает готовую задачу и точные ссылки, а дополнительный контекст открывает только под конкретный технический вопрос.

## Технические режимы проверки

`Writer`, `Reviewer`, `Critic`, `Integrator` - обычно не четыре агента, а последовательные режимы одного локального исполнителя.

Отдельный независимый проверяющий нужен только там, где это действительно требуется задачей или риском.

## Навыки методики и инструменты 1С - разные уровни

Эти навыки описывают **процесс работы**.

Конкретные технические операции выполняют профильные инструменты:

- EDT/MCP - через выбранный EDT-профиль и актуальные MCP-инструменты;
- XML/Конфигуратор - через XML-профиль и подходящие CLI/specs.

Методика не должна создавать отдельный навык на каждую форму, СКД, роль или XDTO, если такую операцию уже умеет профильный инструмент.
