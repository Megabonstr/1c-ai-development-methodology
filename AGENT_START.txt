THIS FILE IS FOR AI AGENTS. DO NOT READ README.md unless the task explicitly edits human docs.

PRE-INSTALL EVALUATION / ADOPTION
If the user gives this methodology URL/ref and asks whether/how to adopt it into another project, no TaskHandle is required. Read .1c-ai/core/ADOPTION.md, inspect the target project read-only, and do not write without explicit authorization.

ROLE ENTRY
Coordinator Main: raw/noisy intent -> TASK_INTAKE/framing/research only as needed -> freeze/correct durable semantic Task Contract -> exact handoff.
Local Main: frozen TaskHandle -> task-bootstrap -> bounded technical discovery/implementation/review/verification -> local verdict/evidence.
Local Main does not reload raw conversation, philosophy, broad history, or semantic decision context by default.
One physical agent may switch roles sequentially; no new chat is required.
Humans need not name skills: route from current intent automatically. Keep exploratory conversation conversational; use task-framing/short clarification only when executable intent is materially noisy or contradictory, and discover cheap technical facts from source instead of asking the human.

DEFAULT READ PATH
1. Resolve the active route and exact durable handle available for that phase; pre-install evaluation may start from the methodology URL/ref without a TaskHandle.
2. Read PROJECT_AI.md when it exists and project-specific identity/constraints are materially needed but not already supplied.
3. Read only the exact core owner section(s) required by the current step.
4. Use .1c-ai/router/ROUTER.md only when workflow/profile/delegation is not already fixed.
5. Load at most one primary workflow skill and one execution profile when needed.
6. Resolve exact source/version/path/symbol/evidence handles. For Git-backed projects prefer repository/ref/SHA handles. Do not roam history/repos/KB.

GIT DEFAULT FOR THIS REPOSITORY
main    = stable accepted state
preprod = integration/release-candidate state
feature/<task> = one bounded task, created from current preprod

Normal delivery:
Issue -> feature from preprod -> implement -> focused checks -> PR to preprod
-> integration/applicable full checks on preprod -> PR preprod to main
-> main only when required gates are green -> close Issue.
No ordinary direct feature -> main delivery.

MERGE STRATEGY
feature -> preprod: squash allowed/preferred for one bounded task.
preprod -> main: normal merge preserving ancestry; DO NOT squash/rebase promotion.
After successful main push CI: fast-forward preprod to accepted main SHA.
Never force-reset branch history for routine synchronization.

ORCHESTRATION
Human Owner + Coordinator Main own product/architecture/task contract/final acceptance/closeout for one explicit CoordinationScope.
Every active task has exactly one OwningCoordinator. Scope may be the whole project or one bounded project/domain area.
Coordinator Main may be cloud/local/desktop/manual-compatible; it owns the authoritative context map, not a full-scope preload.
One Local Main owns local implementation, review, critic pass, verification integration and local verdict.
Ordinary compile/test/metadata/runtime correction stays local. Do not ping-pong to Coordinator Main.
Subagents are optional bounded specialists; read-only by default. Exact isolated write only when explicitly delegated.

SOURCE-FIRST
Current project first.
If mechanism is standard 1C: prefer the applicable standard configuration/BSP implementation and supported public program interface.

DELIVERY DISCIPLINE
Prefer the smallest proven solution that satisfies frozen semantics/scope/safety/acceptance.
Do not add frameworks/generalization/refactors/test infrastructure without a concrete current need.
If a small task expands materially, run a scope/complexity check and cut optional work.
When required acceptance passes: STOP. Record adjacent improvements as separate Issues.

VERIFICATION PROFILE
Default: STANDARD.
FAST_CLIENT_SLICE = narrow urgent bounded client behavior: early safe native/runtime proof, only justified iteration tests, default new-test budget 0-3, one final focused regression + compact result/evidence packet.
HIGH_RISK = destructive/migration/RLS/security/global/high-blast-radius work: broader review/regression/rollback evidence as required.
WORKING_NATIVE_RESULT speeds safe native proof but never bypasses rights/safety/required evidence.
Do not rerun broad suites/full parity/full reports after every micro-fix. Use .1c-ai/core/VERIFICATION_PROFILES.md when needed.

EVIDENCE CODES
SOURCE  = source/design mechanism confirmed
STATIC  = non-runtime validation
TEST    = automated focused tests
BUILD   = artifact/build succeeded
DEPLOY  = applied to target environment
RUNTIME = behavior executed in runtime
NATIVE  = real client/IDE/UI behavior observed
USER_ACCEPTANCE = human acceptance
States: PASS | FAIL | NOT_REQUIRED | UNKNOWN.
Never promote one evidence class into another.
